# Atividade-06---GIT-e-GITHUB
O Git e o GitHub são ferramentas diferentes que frequentemente são usadas juntas para gerenciar o desenvolvimento de software. O Git é o sistema de controle de versão instalado no seu computador, enquanto o GitHub é uma plataforma em nuvem para hospedar esses projetos.

Postar um projeto no GitHub envolve criar um repositório online e enviar os arquivos do seu computador para ele. A maneira mais comum é através do terminal/linha de comando (Git) ou pela interface web.

# GITHUB:
O GitHub é a maior plataforma de hospedagem de código-fonte e colaboração do mundo, utilizando o sistema de controle de versão Git. Ele funciona como uma "rede social para desenvolvedores", permitindo armazenar, compartilhar, revisar e gerenciar projetos de software na nuvem.

Sua principais funções, recursos e comandos são:
Hospedagem de Repositórios: Armazena códigos-fonte e todo o histórico de alterações na nuvem.
Controle de Versão (Git): Permite acompanhar mudanças, reverter para versões anteriores e trabalhar com múltiplas ramificações do código.
Colaboração (Pull Requests): Facilita que múltiplos desenvolvedores trabalhem no mesmo projeto, revisando e mesclando contribuições.
Gestão de Projetos (Issues/Projects): Ferramenta para rastrear bugs, sugerir novas funcionalidades e organizar tarefas.
Automação (GitHub Actions): Permite criar fluxos de CI/CD para testar e publicar códigos automaticamente.
Hospedagem de Sites (GitHub Pages): Publica sites estáticos diretamente de um repositório.
GitHub Copilot: Agente de IA integrado que auxilia no preenchimento automático de código, refatoração e correção de vulnerabilidades diretamente no editor.
GitHub Pages: Hospedagem gratuita de sites estáticos diretamente de um repositório.
GitHub CLI (Command Line Interface): Ferramenta para gerenciar projetos, pull requests e issues diretamente pelo terminal.
GitHub Actions: Pipelines de CI/CD para automatizar fluxos de trabalho.
GitHub Discussions: Fóruns de conversa para a comunidade de um projeto.
Segurança: Escaneamento de vulnerabilidades no código (CodeQL) e automação de alertas.
# Alguns comandos:
git init: Inicializa um novo repositório Git localmente.
git status: Exibe o estado atual (arquivos modificados, preparados, não rastreados).
git add [arquivo]: Adiciona arquivos à área de "staging" (preparação para commit).

# GIT:
O Git é um sistema de controle de versão distribuído (DVCS) projetado para rastrear alterações no código-fonte durante o desenvolvimento de software. Sua principal função é permitir que múltiplos desenvolvedores trabalhem no mesmo projeto simultaneamente, garantindo a integridade do código e permitindo o retorno a versões anteriores se necessário.
Sua principais funções, recursos e comandos são:
Versionamento de Código: Salva "snapshots" (instantâneos) do projeto, permitindo rastrear o histórico e reverter alterações.
Ramificação (Branching): Permite criar ambientes isolados para desenvolver novas funcionalidades ou corrigir bugs sem afetar o código principal (main ou master).
Colaboração Distribuída: Cada desenvolvedor tem uma cópia local completa do repositório, permitindo trabalhar offline e mesclar alterações posteriormente.
Merge (Mesclagem): Integra o trabalho desenvolvido em branches diferentes de volta à linha principal.
Integridade: Tudo é verificado por checksum (SHA-1) antes de ser armazenado, impedindo corrupção de dados.
Área de Staging (Staging Area): Um "palco" intermediário onde você prepara as alterações antes de realizar um commit definitivo.
Stash: Permite salvar temporariamente modificações não finalizadas para alternar entre branches sem perder trabalho.
